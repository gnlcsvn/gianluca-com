Most side projects die in the first week. Not because the idea is bad, but because the scope is too large. I've abandoned enough projects to develop a few rules for finishing them.

## Rule 1: Build the smallest possible version

Before writing any code, I ask: what is the absolute minimum this project needs to be useful? Not impressive, not feature-complete — useful.

For a task manager, that's: add a task, list tasks, mark a task done. Not priorities, not due dates, not categories, not a web interface. Those come later, if at all.

## Rule 2: Set a time constraint

I give myself a weekend or, at most, a week. This isn't about rushing — it's about forcing scope decisions. When time is limited, you cut features ruthlessly. The features that survive are the ones that actually matter.

## Rule 3: Use boring technology

A side project is not the place to learn three new technologies simultaneously. Pick one thing to learn and use familiar tools for everything else. If I'm learning Rust, I'll use SQLite for storage because I already know it. If I'm exploring a new database, I'll write the rest in Go because I'm comfortable with it.

## Rule 4: Ship something

"Ship" doesn't have to mean deploy to production. It means: reach a state where the project does something useful and could be shown to another person. Push it to GitHub. Write a two-sentence README. Call it done.

An imperfect, shipped project teaches more than a perfect, unfinished one.

## Rule 5: It's okay to stop

Not every side project needs to become a maintained open-source library. Sometimes you build something, learn what you wanted to learn, and move on. That's a success, not a failure.

## The pattern that works for me

1. Saturday morning: write down the idea, list the minimum features
2. Saturday afternoon: build the core functionality
3. Sunday: polish rough edges, write a README, push to GitHub
4. Monday: resist the urge to add features

---

The goal of a side project is to learn something or scratch an itch. Finishing is more important than perfecting.
